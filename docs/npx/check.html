Collision Guard • Pre-flight Verification

npx caddy-subdomain check

Pre-flight collision guard. Test whether a subdomain is already configured in Caddy before adding routes or running deployment scripts.

Live Production Syntax:
npx caddy-subdomain check quotation.keshavsoft.com /etc/caddy/caddy.json

The Problem & Story

In automated deployment pipelines, shell scripts, or multi-developer teams, accidentally registering an existing subdomain can overwrite a production route or cause conflicting matchers.

The Solution: Run check <domain>! It performs a case-insensitive check and immediately returns whether the domain is available or already registered on your server.

Output States

State: Domain Already Exists
❌ Domain 'quotation.keshavsoft.com' is ALREADY configured in /etc/caddy/caddy.json
State: Domain Available
✅ Domain 'newapp.keshavsoft.com' is AVAILABLE to be added

Shell Scripting & Automation

Check domain availability before provisioning in bash scripts:

#!/usr/bin/env bash
DOMAIN="call.keshavsoft.com"

# Verify domain isn't already taken:
if npx caddy-subdomain check "$DOMAIN" | grep -q "ALREADY"; then
  echo "Domain already in use! Exiting..."
  exit 1
fi

# Safe to proceed with Level 1 probe:
npx caddy-subdomain probe "$DOMAIN" --reload
