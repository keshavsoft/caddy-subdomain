Level 1 Flight Check • Zero Dependencies

npx caddy-subdomain probe

Test DNS propagation and auto-provision your Let's Encrypt / ZeroSSL certificate without starting Node.js or allocating backend ports.

Live Production Syntax:
npx caddy-subdomain probe call.keshavsoft.com /etc/caddy/caddy.json --reload

The Problem & Story

Whenever you configure a new subdomain (e.g. creating an A record on GoDaddy pointing to your server IP), your immediate instinct is often to start your Node.js application, configure PM2, and map reverse proxy ports.

The Problem: When you open the browser and it fails to load, you're left guessing: Did DNS propagate? Is port 443 blocked by a firewall? Did Caddy fail to issue the SSL certificate? Or did the Node.js process crash?

The Solution: Run probe first! It injects Caddy's native static_response handler. When you open https://your-domain.com and see the Green Padlock with a 200 OK message, you have 100% mathematical proof that DNS, firewall, and SSL are working.

Under The Hood: Generated Caddy JSON

Notice that this route requires zero open ports and zero files on disk:

{
  "match": [{ "host": ["call.keshavsoft.com"] }],
  "handle": [
    {
      "handler": "static_response",
      "status_code": 200,
      "headers": { "Content-Type": ["text/plain; charset=utf-8"] },
      "body": "✅ Subdomain 'call.keshavsoft.com' is LIVE on Caddy!\nDNS propagation and Automatic HTTPS (SSL) verified successfully.\n"
    }
  ],
  "terminal": true
}

Supported Options & Flags

Flag Type Description
--reload Boolean Triggers caddy reload --config <file> immediately after writing.
--force Boolean Bypasses duplicate domain check and replaces existing configuration.
--no-backup Boolean Skips creating the timestamped .bak.<timestamp> file.
